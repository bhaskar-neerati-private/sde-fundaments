1.5 Linked Lists

Objective: implement singly and doubly linked lists from scratch and manipulate them (reverse, detect cycle, merge) without relying on Python's built-in list.

1.5a Singly Linked Lists

A linear structure of nodes, each storing a value and a reference (next) to the following node. Represented by a reference to the first node (head); the last node's next is None. Nodes need not be contiguous in memory.

Plain English: arrays give O(1) random access via arithmetic on contiguous memory. Linked lists can't do that - reaching node 5 means walking through nodes 1-4, one hop at a time. In exchange, insert/delete is O(1) once you have a pointer to the spot - no shifting elements, unlike an array insert at the front (O(n)).

Analogy: a scavenger hunt where each clue reveals the next clue's location (vs. a map with everything marked, i.e. an array). Inserting a new clue between #2 and #3 just changes what #2 points to - O(1), regardless of hunt length.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class SinglyLinkedList:
    def __init__(self):
        self.head = None

    def insert_front(self, data):            # O(1)
        new_node = Node(data)
        new_node.next = self.head
        self.head = new_node

    def insert_back(self, data):               # O(n) - no tail pointer kept
        new_node = Node(data)
        if not self.head:
            self.head = new_node
            return
        curr = self.head
        while curr.next: curr = curr.next
        curr.next = new_node

    def delete(self, data):                     # O(n)
        if not self.head: return
        if self.head.data == data:
            self.head = self.head.next
            return
        curr = self.head
        while curr.next and curr.next.data != data:
            curr = curr.next
        if curr.next:
            curr.next = curr.next.next

    def traverse(self):                          # O(n)
        result, curr = [], self.head
        while curr:
            result.append(curr.data)
            curr = curr.next
        return result

In-place reversal - O(n) time, O(1) space (the classic checkpoint ask):

def reverse(self):
    prev = None
    curr = self.head
    while curr:
        next_node = curr.next   # save BEFORE overwriting curr.next
        curr.next = prev
        prev = curr
        curr = next_node
    self.head = prev

Trace on 1 → 2 → 3 → None:

  • Start: prev=None, curr=1
  • Iter1: next_node=2; 1.next=None; prev=1, curr=2
  • Iter2: next_node=3; 2.next=1; prev=2, curr=3
  • Iter3: next_node=None; 3.next=2; prev=3, curr=None → loop ends
  • head = prev = 3 → 3 → 2 → 1 → None

The reason this is O(1) space: next_node is saved before curr.next is overwritten, so the rest of the original list is never lost mid-rewire. Overwrite-then-save would strand it, unreachable.

1.5b Doubly Linked Lists, Cycle Detection & Merging

Doubly linked list: each node holds a value plus two references - next and prev - enabling traversal in both directions; typically keeps both head and tail.

Plain English: in a singly linked list, deleting a node requires already having its predecessor (found by traversing from head), since the predecessor's .next is what needs to change. A doubly linked list stores .prev directly, so deletion given any node reference is O(1) - no traversal needed. Cost: every insert/delete wires up 4 pointers instead of 2, plus more memory per node.

Analogy: singly linked = one-way street (only forward signs). Doubly linked = two-way street (both signs visible from anywhere, no backtracking to the start).

class DNode:
    def __init__(self, data):
        self.data = data
        self.prev = None
        self.next = None

class DoublyLinkedList:
    def __init__(self):
        self.head = None
        self.tail = None

    def insert_front(self, data):
        new_node = DNode(data)
        if not self.head:
            self.head = self.tail = new_node
            return
        new_node.next = self.head
        self.head.prev = new_node
        self.head = new_node

    def delete_node(self, node):          # O(1) given a direct reference
        if node.prev: node.prev.next = node.next
        else: self.head = node.next
        if node.next: node.next.prev = node.prev
        else: self.tail = node.prev

Cycle detection - Floyd's Tortoise and Hare: advance a slow pointer 1 node/step and a fast pointer 2 nodes/step; if they ever become equal, there's a cycle. No cycle → fast reaches None first.

Plain English: without a cycle, the faster pointer just reaches the end first. With a cycle, fast closes the gap on slow by exactly one extra step every iteration, so it's guaranteed to eventually land on slow's position.

Analogy: two runners on a track, one twice as fast. Straight finite road (no cycle) - faster one just finishes, never "catches" the other. Looped track (cycle) - faster runner eventually laps the slower one, landing at the same spot.

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast: return True
    return False

Finding the cycle's start - reset one pointer to head, keep the other at the meeting point, advance both one step at a time; they meet exactly at the cycle's start:

def find_cycle_start(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast: break
    else:
        return None
    ptr = head
    while ptr is not slow:
        ptr = ptr.next
        slow = slow.next
    return ptr

Why this works: let a = steps from head to cycle start, c = cycle length, x = steps slow took inside the cycle before meeting fast. At the meeting point, fast traveled exactly double slow's distance, so the extra distance (a + x) must be a whole number of laps: a + x = k·c. That means the remaining distance from the meeting point forward to the cycle start (c - x) is congruent to a - so a pointer walking a steps from head, and one walking that same distance from the meeting point, land together exactly at the cycle's start.

Merging two sorted linked lists - O(n+m) time, O(1) extra space (pure pointer rewiring, no new nodes):

def merge_two_sorted(l1, l2):
    dummy = Node(None)
    tail = dummy
    while l1 and l2:
        if l1.data <= l2.data:
            tail.next = l1; l1 = l1.next
        else:
            tail.next = l2; l2 = l2.next
        tail = tail.next
    tail.next = l1 if l1 else l2
    return dummy.next

Analogy: merging two sorted decks of cards face-up, always taking the smaller visible top card; once one deck empties, dump the rest of the other (already sorted) on top.

The dummy head node is the same "padding avoids a special case" trick as 1.4c's padded prefix-sum array - it absorbs "what's the first node of the result" so the loop never needs an if this is the first node branch.
