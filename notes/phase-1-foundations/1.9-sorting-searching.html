1.9 Sorting & Searching

Objective: implement merge sort, quicksort, and binary search from memory; know their complexities and trade-offs cold.

1.9a Merge Sort & Quicksort

Merge sort: divide-and-conquer - recursively split in half until each piece is one element (trivially sorted), then repeatedly merge pairs of sorted pieces back together. O(n log n) in every case (best/average/worst), O(n) auxiliary space, stable.

Analogy: sorting exam papers by splitting the stack in half among study groups repeatedly until each has one paper, then merging pairs of sorted stacks by always taking whichever top paper is smaller, building progressively bigger sorted stacks.

def merge_sort(arr):
    if len(arr) <= 1: return arr
    mid = len(arr) // 2
    left, right = merge_sort(arr[:mid]), merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:          # <=, not < -- this is what makes it STABLE
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:]); result.extend(right[j:])
    return result

Why <= for stability: on a tie, taking from left first keeps it ahead of the equal element from right, matching original relative order (everything in left came from earlier in the array). Strict < taking from right on ties could flip equal elements' relative order.

Complexity, mechanically: log n levels of splitting, O(n) merge work per level → O(n log n) total.

Quicksort: picks a pivot, partitions so smaller elements precede it and larger follow (pivot lands in its final position), recurses on the two partitions independently. Average O(n log n), worst O(n²) (bad pivot on adversarial/sorted input), typically in-place (O(log n) space), not stable.

Analogy: lining people up by height around a reference person - everyone shorter moves to one side, taller to the other; the reference person is now permanently in their correct final spot. Repeat independently within each side.

def quicksort(arr, lo=0, hi=None):
    if hi is None: hi = len(arr) - 1
    if lo < hi:
        p = partition(arr, lo, hi)
        quicksort(arr, lo, p - 1)
        quicksort(arr, p + 1, hi)
    return arr

def partition(arr, lo, hi):              # Lomuto scheme
    pivot = arr[hi]
    i = lo - 1
    for j in range(lo, hi):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]
    arr[i + 1], arr[hi] = arr[hi], arr[i + 1]
    return i + 1

Trace on [3,6,2,8,4] (pivot=4): after the loop, i=1; final swap puts 4 at index 2 → [3,2,4,8,6] - everything before ≤4, everything after >4. Recurse on [3,2] and [8,6] independently.

Worst case: already-sorted input + always picking the last element as pivot → maximally unbalanced partitions every time → O(n) recursion depth, O(n²) total work. Mitigation: random pivot selection - doesn't change the theoretical worst case, but makes it astronomically unlikely on real data.

Comparison:

Merge sort Quicksort
Time O(n log n) guaranteed O(n log n) avg, O(n²) worst
Space O(n) O(log n) in-place
Stable? Yes No

Real-world tie-in: Python's sorted()/list.sort() uses Timsort (merge-sort-based hybrid) specifically for stability, guaranteed O(n log n) worst case, and adaptiveness (O(n) on nearly-sorted real data). C++'s std::sort typically uses introsort (quicksort/heapsort/insertion-sort hybrid, switching to heapsort if recursion gets suspiciously deep to avoid quicksort's O(n²) worst case).

1.9b Binary Search

Finds a target within a monotonic search space by repeatedly halving the range: compare the midpoint against the target/condition, discard the half that provably cannot contain the answer, repeat until the range narrows to zero/one elements. O(log n).

Plain English: "sorted array lookup" undersells it. The real generalizable idea: if you can define a yes/no question over a space such that all "no"s come before all "yes"s (monotonic), you can binary search on that condition to find the boundary - even when you're not looking up a literal value in a literal array. This generalization is what lets you binary search over an answer space (e.g. "what's the minimum capacity that works?"), not just array indices.

Analogy: guessing a number 1–100 with only "higher/lower" answers - each guess eliminates half the remaining possibilities regardless of where the actual number sits.

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target: return mid
        elif arr[mid] < target: lo = mid + 1
        else: hi = mid - 1
    return -1

Search in a rotated sorted array (e.g. [4,5,6,7,0,1,2], sorted then rotated at an unknown pivot) - still O(log n): at any midpoint, at least one half is guaranteed normally sorted (the rotation break can only exist in one of the two halves). Check which half is sorted, determine whether the target falls in that half's range, and recurse into the appropriate side.

def search_rotated(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target: return mid
        if arr[lo] <= arr[mid]:                        # left half is sorted
            if arr[lo] <= target < arr[mid]: hi = mid - 1
            else: lo = mid + 1
        else:                                            # right half is sorted
            if arr[mid] < target <= arr[hi]: lo = mid + 1
            else: hi = mid - 1
    return -1

Binary search on the answer - a general template for monotonic predicates over a range of candidate answers rather than an array:

def binary_search_on_answer(lo, hi, feasible):
    # feasible(x): False...False, True...True (monotonic) over [lo, hi]
    while lo < hi:
        mid = (lo + hi) // 2
        if feasible(mid): hi = mid          # try to find a smaller feasible value
        else: lo = mid + 1
    return lo                                # smallest x where feasible(x) is True

Same halving idea, applied to a candidate-answer range instead of array indices - used for problems like "minimum shipping capacity to deliver within D days," where feasible(capacity) is monotonic (once a capacity works, every larger capacity also works).
