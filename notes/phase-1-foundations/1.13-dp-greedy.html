1.13 Dynamic Programming & Greedy Algorithms

Objective: recognize overlapping subproblems and optimal substructure; convert brute-force recursion into memoized/tabulated DP; know when greedy is provably correct vs. when it isn't.

1.13a From Recursion to Memoization to Tabulation

Dynamic programming solves problems with overlapping subproblems (the same subproblem recurs many times in naive recursion) and optimal substructure (an optimal solution is built from optimal solutions to subproblems), by caching subproblem results as computed (memoization, top-down) or building a table iteratively from the base case forward (tabulation, bottom-up) - both avoid the redundant recomputation that makes naive recursion exponential.

Analogy: keeping a running FAQ sheet while doing homework - the first time "what's 7×8" comes up mid-problem, you write the answer down; every later occurrence of that exact sub-question, you glance at the sheet instead of recomputing, since the underlying math never changes between occurrences.

def fib_naive(n):                          # O(2^n) - recomputes everything
    if n <= 1: return n
    return fib_naive(n-1) + fib_naive(n-2)

def fib_memo(n, cache=None):                 # O(n) time, O(n) space (cache + stack) - top-down
    if cache is None: cache = {}
    if n <= 1: return n
    if n not in cache:
        cache[n] = fib_memo(n-1, cache) + fib_memo(n-2, cache)
    return cache[n]

def fib_tab(n):                                # O(n) time, O(n) space - bottom-up, no recursion
    if n <= 1: return n
    table = [0] * (n + 1)
    table[1] = 1
    for i in range(2, n + 1):
        table[i] = table[i-1] + table[i-2]
    return table[n]

def fib_tab_optimized(n):                        # O(1) space - only the last 2 values matter
    if n <= 1: return n
    prev2, prev1 = 0, 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev2 + prev1
    return prev1

The progression: naive recomputes the same subproblems exponentially many times; memoization caches each distinct subproblem's answer the first time (still uses the recursion stack); tabulation flips it bottom-up, avoiding recursion entirely, and often unlocks further space optimization since only the last few table entries are usually needed, not the whole table.

1.13b Classic DP Patterns

0/1 Knapsack: maximize total value of items within a weight capacity, each item usable at most once.
Recurrence: dp[i][w] = best value using the first i items with capacity w.

def knapsack(weights, values, capacity):
    n = len(weights)
    dp = [[0] * (capacity + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        for w in range(capacity + 1):
            if weights[i-1] > w:
                dp[i][w] = dp[i-1][w]                                        # can't include item i
            else:
                dp[i][w] = max(dp[i-1][w], dp[i-1][w - weights[i-1]] + values[i-1])  # exclude vs include
    return dp[n][capacity]

LCS (Longest Common Subsequence): length of the longest subsequence (order-preserving, not necessarily contiguous) common to two strings.

def lcs(s1, s2):
    m, n = len(s1), len(s2)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]

LIS (Longest Increasing Subsequence), O(n²) baseline: dp[i] = length of the longest increasing subsequence ending exactly at index i.

def lis(arr):
    if not arr: return 0
    n = len(arr)
    dp = [1] * n
    for i in range(n):
        for j in range(i):
            if arr[j] < arr[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)

(An O(n log n) version exists using binary search + patience sorting - know the O(n²) DP baseline cold first.)

1.13c Greedy Algorithms

A greedy algorithm builds a solution by repeatedly making the locally optimal choice at each step, never reconsidering it, hoping - and for provably-greedy problems, guaranteeing - that the sequence of local choices produces a globally optimal solution. Greedy is not always correct: it only works for problems with the right structure (the "greedy-choice property" plus optimal substructure); applying it elsewhere gives a locally-sensible but globally wrong answer.

Plain English: greedy never looks back, never explores alternatives. For some problems (activity selection, Dijkstra's - non-negative weights, Huffman coding) this provably always finds the true best answer. For others (0/1 knapsack in general) greedy gives a plausible but genuinely wrong answer, because an early "obviously good" choice can foreclose a better combination later.

Analogy: picking which classes to attend today by always choosing whichever currently-available class ends soonest (freeing you up sooner). This "shortest remaining first" greedy strategy provably maximizes the number of classes attendable in a day (classic activity selection). But if instead maximizing total value of classes attended (value unrelated to duration), that same greedy strategy could easily lock in a bad early choice and land on a worse total than a more careful plan.

def max_activities(activities):        # provably correct greedy - list of (start, end)
    activities.sort(key=lambda x: x[1])  # always pick earliest-ending next
    count, last_end = 0, float('-inf')
    for start, end in activities:
        if start >= last_end:
            count += 1
            last_end = end
    return count

def can_jump(nums):                      # jump game - another classic greedy
    max_reach = 0
    for i, n in enumerate(nums):
        if i > max_reach: return False    # can't even reach this index
        max_reach = max(max_reach, i + n)
    return True

How to tell if greedy is actually valid: try to construct an exchange argument - show that any optimal solution can be modified to include the greedy choice without making it worse. If you can't construct one, and can't find a counterexample either, don't trust greedy blindly - default to DP unless greedy correctness is provable.
