1.12 Graphs

Objective: implement BFS, DFS, topological sort, and Dijkstra's algorithm from scratch; recognize which traversal a problem needs.

1.12a Graph Representation, BFS & DFS

Adjacency list (dict of node → list of neighbors): O(V+E) space, efficient for sparse graphs, iterating a node's neighbors costs O(degree). Adjacency matrix (2D array, matrix[i][j] = edge weight/presence): O(V²) space, O(1) edge-existence check, wasteful for sparse graphs. Default to adjacency lists unless the graph is dense or you need O(1) edge lookups constantly.

BFS (see 1.6b for the full breakdown): queue-based, explores level by level, guarantees shortest path in an unweighted graph.

DFS: explores as deep as possible down one path before backtracking, using either explicit recursion (the call stack) or an explicit stack.

def dfs_recursive(graph, node, visited=None):
    if visited is None: visited = set()
    visited.add(node)
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs_recursive(graph, neighbor, visited)
    return visited

def dfs_iterative(graph, start):
    visited, stack, order = {start}, [start], []
    while stack:
        node = stack.pop()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                stack.append(neighbor)
    return order

Analogy: DFS is solving a maze by always taking the first unexplored path and going as deep as possible before backtracking (like keeping one hand on the left wall). BFS is ripples spreading outward evenly from a dropped stone - same underlying "swap the container" relationship as 1.6b: DFS uses a stack (LIFO), BFS uses a queue (FIFO).

1.12b Topological Sort

Orders the nodes of a DAG (Directed Acyclic Graph) so that for every edge u → v, u comes before v - only possible if the graph has no cycles. Kahn's algorithm: repeatedly remove nodes with in-degree 0 (no remaining prerequisites), append to the result, and decrement the in-degree of their neighbors as they're "removed." If every node gets processed, that's a valid order; if some remain stuck (in-degree never reaches 0), the graph has a cycle.

Analogy: doing tasks with prerequisites - you can only start a task once all its prerequisites are done. Repeatedly pick any currently-available task (no unfinished prerequisites), do it, then check which new tasks just became available.

from collections import deque

def topological_sort(graph, num_nodes):
    in_degree = [0] * num_nodes
    for node in graph:
        for neighbor in graph[node]:
            in_degree[neighbor] += 1
    queue = deque([n for n in range(num_nodes) if in_degree[n] == 0])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            in_degree[neighbor] -= 1
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
    if len(order) != num_nodes:
        raise ValueError("graph has a cycle -- no valid topological order")
    return order

1.12c Dijkstra's Algorithm

Finds shortest paths from a source to all other nodes in a graph with non-negative edge weights, using a min-heap to always process the currently-closest unvisited node next, and relaxing (updating) neighbor distances whenever a shorter path through the current node is found.

Plain English: like BFS, but weighted. BFS processes nodes in discovery order (all edges cost 1); Dijkstra always processes whichever undiscovered node currently has the smallest known distance-from-source, using the heap to find that efficiently each time.

Analogy: a road-trip planner that always finishes exploring routes to the currently-cheapest-to-reach city before considering any pricier one - guaranteeing that once a city is "finalized," no cheaper route to it can turn up later, since every additional road segment costs something non-negative and can only add cost, never reduce it.

import heapq

def dijkstra(graph, start):        # graph: node -> list of (neighbor, weight)
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    pq = [(0, start)]
    visited = set()
    while pq:
        dist, node = heapq.heappop(pq)
        if node in visited: continue
        visited.add(node)
        for neighbor, weight in graph[node]:
            new_dist = dist + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist
                heapq.heappush(pq, (new_dist, neighbor))
    return distances

O((V+E) log V) with a binary heap.

Why non-negative weights are required: if negative weights were allowed, a node already finalized (popped, visited) might later be reachable more cheaply via a path through a negative edge - breaking the greedy guarantee that popping = done. (Bellman-Ford handles negative weights instead, outside this lesson's scope.)
