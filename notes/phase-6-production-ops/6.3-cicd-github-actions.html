6.3 CI/CD with GitHub Actions

Objective: build a pipeline that runs tests and lints on every push, and only builds/pushes a Docker image on merge to main - the actual point of CI/CD, not just "a YAML file exists."

A CI/CD pipeline is an automated workflow, triggered by repository events (a push, a PR), running a defined sequence of steps - install dependencies, run linters/tests (Continuous Integration - catching problems early, on every change), and conditionally, only on specific triggers (e.g. merge to main), build and deploy an artifact (Continuous Deployment/Delivery).

Plain English: the point isn't "a YAML file exists" - it's that every change gets automatically verified (tests/lints on every push/PR, catching regressions before they reach main), and deployment only happens from a known-good, tested state (merges to main that already passed CI), never from arbitrary in-progress branches. Building/pushing a Docker image on every PR branch would waste resources on code that might never even get merged, and risks accidentally deploying unfinished, experimental work.

Analogy: a factory quality-control checkpoint every batch must pass through before shipping (tests run on every push) - but the actual shipping/packaging step (building & pushing the deployable image) only happens for batches that passed final approval (merged to main), not for every prototype still on the factory floor (PR branches).

# .github/workflows/ci.yml
name: CI/CD
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:

      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }

      - run: pip install -r requirements.txt
      - run: pytest                            # runs on EVERY push and PR -- fails the build on test failure

  build-and-push:
    needs: test
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main' && github.event_name == 'push'   # ONLY on merge to main
    steps:

      - uses: actions/checkout@v4
      - run: docker build -t ghcr.io/myorg/myapp:${{ github.sha }} .
      - run: docker push ghcr.io/myorg/myapp:${{ github.sha }}

Why the image-push step should never run on every PR branch: it wastes build time and registry storage on artifacts that may never be deployed (a PR might never merge, or might change dozens of times before merging), and risks someone accidentally pulling/running an unreviewed, unmerged image tag in a context where only reviewed code should run.
