Phase 1: Foundations

  • Duration: 3.5–4.5 weeks at 15–20 hrs/week (~50–75 hrs total)
  • Builds on: nothing - this is the base layer.
  • Unlocks: everything else. Phase 4 (design) and Phase 5 (distributed systems) assume you can reason about time/space complexity and pick the right data structure without hesitating.
  • Adjusted for your profile: nothing is skipped, including Programming Fundamentals (1.1) - but it isn't taught as a beginner crawl either. Since you already write code comfortably, that lesson is framed as a rigorous audit: surface the gaps "comfortable" hides (dunder methods, generators, decorators, exception design) rather than re-teaching syntax you already know.

Read the tutor model in the README before starting if you haven't - every checkpoint below is a gate, not a suggestion.

How to read this file: each numbered lesson (1.1, 1.2, ...) is a unit with its own Watch/Read/Do/Checkpoint - that's the thing that must pass before you move on. Underneath each one, "Teaching sessions" breaks it into the ~40-minute chunks I'll actually teach you in chat, one sitting at a time. A lesson with only one teaching session is small enough to cover in a single sitting; a lesson with 1.4a/1.4b/1.4c means we'll do it across 3 sittings before its checkpoint.

1.1 Programming Fundamentals (Python)

Objective: Close the gap between "comfortable writing code" and actually knowing the language - control flow, functions, OOP, exceptions, and the features many self-taught-comfortable coders never formally learn (comprehensions, generators, decorators, context managers). This lesson is an audit, not a first exposure: move fast through what you already know, slow down hard on whatever you don't.

Teaching sessions (~40 min each):

  • 1.1a Objects, Classes & Dunder Methods - classes, __init__, inheritance, and the "magic methods" (__repr__, __eq__, etc.) that make your objects behave like Python's built-ins.
  • 1.1b Comprehensions & Generators - list/dict/set comprehensions, and generator expressions/yield for when you shouldn't build the whole list at once.
  • 1.1c Decorators - functions as first-class objects, closures, and the @decorator syntax.

  • 1.1d Context Managers & Custom Exceptions - the with statement, __enter__/__exit__, and designing your own exception classes instead of over-using generic ones.

  • Watch: Learn Python - Full Course for Beginners (freeCodeCamp) (~4.5 hrs - skim or skip sections you can already do blind, but don't skip OOP and exception handling), plus three targeted Corey Schafer videos on the features a "comfortable" coder most often never properly learned: Comprehensions, Generators, and Decorators

  • Read: The Python Tutorial - official docs
  • Do / Checkpoint - 5 specific problems, no reference material, closed-book. Solve all five, then walk through each solution and justify every choice under questioning - "I copied the pattern but can't explain it" fails, regardless of whether the code runs.
    1. Dunders: Build a Fraction class storing a numerator and denominator. Implement __repr__ returning exactly Fraction(a, b) format. Implement __eq__ so it compares by value, not identity - Fraction(1, 2) == Fraction(2, 4) must be True. Implement __add__ so Fraction(1, 2) + Fraction(1, 3) returns a Fraction equal to Fraction(5, 6).
    2. Comprehension vs. generator: Given nums = list(range(100_000)), write a list comprehension producing the squares of only the even numbers, then the identical logic as a generator expression. Using sys.getsizeof, print the actual byte size of each and explain the difference in one sentence tied to eager vs. lazy evaluation.
    3. Decorator: Write @log_calls, applied to def add(a, b): return a + b, that prints Calling add(3, 5) before running it and add returned 8 after. Use functools.wraps and prove it worked by asserting add.__name__ == "add" after decoration (not "wrapper").
    4. Context manager: Write a Timer context manager (class-based or @contextmanager, your choice - be ready to justify which and why) that prints the elapsed time when a with block exits. Prove the guarantee: put raise ValueError("test") inside the block and show the elapsed-time message still prints before the exception propagates.
    5. Custom exceptions: Build a Stack with a pop() that raises EmptyStackError (inheriting from a base StackError) when called on an empty stack, carrying a message. Show it caught two ways: once via except EmptyStackError, once via except StackError - both must work, proving the hierarchy.

1.2 Git & GitHub Essentials

Objective: Use Git confidently for branching, merging, rebasing, and resolving conflicts - not just add/commit/push.

Teaching sessions (~40 min each):

  • 1.2a Commits, Branches & Merging - what a commit actually is, how branches work, and what merge is doing under the hood.

  • 1.2b Rebasing & Conflict Resolution - interactive rebase, squashing, and resolving conflicts by hand instead of panicking.

  • Watch: Git & GitHub Crash Course for Beginners (freeCodeCamp, 2026) (~81 min)

  • Read: Git and GitHub learning resources - GitHub Docs
  • Do: Create a throwaway repo. Make 3 branches, deliberately create a merge conflict between two of them and resolve it by hand. Then do an interactive rebase to squash 3 commits into 1.

Checkpoint:

  • Closed-book: explain the difference between merge and rebase, and when you'd use each, without looking anything up.
  • Practical: show the resolved merge conflict and the squashed history from the exercise.
  • Pass bar: correct explanation + working repo history. If you can't explain why rebase rewrites history, redo before moving on.

1.3 Big-O and Algorithmic Thinking

Objective: Look at any snippet of code and state its time/space complexity within seconds; know when O(n log n) vs O(n²) actually matters in practice.

Teaching sessions (~40 min): one sitting - this is a single coherent idea (how to measure "how much work code does") taught progressively; no split needed.

  • Watch: Big-O Notation - For Coding Interviews (NeetCode)
  • Read: Big-O Notation - Khan Academy and §3.3 Big-O Notation - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python, Analysis chapter
  • Do: Write 10 short Python snippets of your own (nested loops, recursion, hash lookups, string slicing) and annotate each with its time and space complexity plus a one-sentence justification.

Checkpoint: Closed-book - have someone (or me, in this project) give you 5 unseen snippets; state complexity out loud within 30 seconds each, with correct justification. 4/5 minimum to pass.

1.4 Arrays & Strings

Objective: Fluently apply two-pointer, sliding-window, and prefix-sum techniques.

Teaching sessions (~40 min each):

  • 1.4a Two Pointers - opposite-end pointers closing in on each other.
  • 1.4b Sliding Window - a window that grows/shrinks as it moves across the array.

  • 1.4c Prefix Sums - precomputing running totals so range-sum queries become instant.

  • Watch: the Arrays/Strings sections of Data Structures and Algorithms in Python – Full Course (freeCodeCamp)

  • Read: Two Pointers and Introduction to Prefix Sums - USACO Guide. Note: the Runestone Academy textbook used elsewhere in this phase doesn't cover these interview-style array patterns at all (it's a classical-ADT textbook, not a pattern guide) - USACO Guide is the best free, well-structured alternative for this specific topic.
  • Do: Using the NeetCode roadmap, solve 8 Arrays/Two-Pointers problems unaided and closed-book before checking any solution.

Checkpoint: Timed - 3 medium-difficulty array/string problems in 60 minutes, no notes. 2/3 correct minimum, and before coding each you must state out loud which technique (two-pointer / sliding-window / prefix-sum) applies and why.

1.5 Linked Lists

Objective: Implement singly and doubly linked lists from scratch and manipulate them (reverse, detect cycle, merge) without relying on Python's built-in list.

Teaching sessions (~40 min each):

  • 1.5a Singly Linked Lists - nodes, pointers, insert/delete/reverse.

  • 1.5b Doubly Linked Lists, Cycle Detection & Merging - backward pointers, Floyd's cycle-detection ("tortoise and hare"), merging two sorted lists.

  • Watch: the Linked Lists section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: §4.19–4.23 ("Lists" through "Implementing an Ordered List") in the Basic Data Structures chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python - note: there's no standalone "Linked Lists chapter" in this book; linked lists are the last third of the Basic Data Structures chapter, alongside stacks/queues/deques.
  • Do: Implement a singly linked list class (insert front/back, delete, reverse) and a doubly linked list, from raw node objects - no collections.deque, no built-in list. Then solve 5 NeetCode linked-list problems (reverse list, detect/remove cycle, merge two sorted lists).

Checkpoint: Build from scratch, unaided - reverse a linked list in-place with O(1) space, on a whiteboard/blank file, no reference code visible. Must get pointer manipulation correct without off-by-one errors on the first or second attempt.

1.6 Stacks & Queues

Objective: Know when a problem is secretly a stack or queue problem (matching brackets, monotonic stack, BFS ordering) and implement both from scratch.

Teaching sessions (~40 min each):

  • 1.6a Stacks & the Monotonic Stack Pattern - LIFO, matching brackets, and the monotonic-stack trick for "next greater element"-style problems.

  • 1.6b Queues & BFS Ordering - FIFO, and why BFS specifically needs a queue (not a stack).

  • Watch: the Stacks/Queues section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: §4.5–4.18 (Stacks through Deques) in the Basic Data Structures chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python - one chapter, not two separate ones as the name might suggest.
  • Do: Implement a stack and a queue using only arrays (no collections.deque). Solve NeetCode's Stack section (valid parentheses, min stack, monotonic stack problem, evaluate RPN).

Checkpoint: Closed-book - given an unseen problem, correctly identify within 2 minutes whether it's a stack or queue pattern and justify why. Then implement the solution correctly.

1.7 Hash Tables

Objective: Understand how a hash map actually works under the hood (buckets, collision resolution, amortized O(1)) - not just dict[key] = value.

Teaching sessions (~40 min each):

  • 1.7a What Hashing Actually Is - hash functions, buckets, why lookup is (usually) O(1).

  • 1.7b Collision Resolution & Building One From Scratch - separate chaining vs. open addressing, then implementing a hash map yourself.

  • Watch: the Hashing section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: §6.5 Hashing - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python, Sorting and Searching chapter - hashing lives inside the Sorting and Searching chapter in this book, not its own chapter.
  • Do: Implement a hash map from scratch using an array of buckets and separate chaining (or open addressing) for collision resolution - no built-in dict. Then solve NeetCode's Hashing section (two sum, group anagrams, top-k frequent).

Checkpoint: Closed-book explanation - explain what happens internally when two keys hash to the same bucket, and why average-case lookup is still O(1). Practical: your from-scratch hash map passes a 20-case unit test you write yourself (insert, lookup, delete, collision cases).

1.8 Recursion & Backtracking

Objective: Write recursive solutions without tracing through them on paper first; recognize backtracking problems (permutations, combinations, N-Queens-style) on sight.

Teaching sessions (~40 min each):

  • 1.8a Recursion Fundamentals - base case, recursive case, and how to trust the recursion instead of mentally unwinding the whole call stack.

  • 1.8b Backtracking - recursion plus "undo the choice and try the next one" - the choice/constraint/goal framework.

  • Watch: the Recursion/Backtracking section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: the Recursion chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python for recursion fundamentals, plus Chapter 2: Backtracking - Algorithms, Jeff Erickson (free, UIUC) for backtracking specifically - the Runestone book covers basic recursion but has no backtracking chapter at all, so this is a genuinely different book, not a substitute citation.
  • Do: Solve NeetCode's Backtracking section (subsets, permutations, combination sum, word search) - at least 6 problems, closed-book first attempt.

Checkpoint: Build from scratch, unaided - write a backtracking solution to an unseen problem (e.g. generate all valid parentheses combinations) in under 20 minutes, correctly identifying the choice/constraint/goal structure before coding.

1.9 Sorting & Searching

Objective: Implement merge sort, quicksort, and binary search from memory; know their complexities and trade-offs cold.

Teaching sessions (~40 min each):

  • 1.9a Merge Sort & Quicksort - divide-and-conquer sorting, and why one is stable/predictable and the other is usually faster in practice but has a worst case.

  • 1.9b Binary Search - not just "sorted array lookup" - the general pattern of searching any monotonic space, including "search in rotated sorted array."

  • Watch: the Sorting/Searching section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: the Sorting and Searching chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python
  • Do: Implement merge sort, quicksort, and binary search (including "search in rotated sorted array" variant) from scratch, no sorted()/sort(). Solve 5 NeetCode binary-search problems.

Checkpoint: Closed-book, timed - implement merge sort AND binary search correctly, from memory, in under 25 minutes combined, no reference material.

1.10 Trees & Binary Search Trees

Objective: Implement tree traversals (in/pre/post-order, BFS level-order) and BST operations (insert, search, delete) from scratch; reason about balanced vs unbalanced trees.

Teaching sessions (~40 min each):

  • 1.10a Tree Traversals - in-order, pre-order, post-order (recursive) and level-order (BFS with a queue) - and when you'd want each.

  • 1.10b Binary Search Trees - the BST invariant, insert/search, and the tricky delete-with-two-children case.

  • Watch: the Trees section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: the Trees and Tree Algorithms chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python (BST specifically is §7.11)
  • Do: Implement a BST with insert/search/delete (including the delete case with two children) and all four traversal orders, recursively and iteratively. Solve NeetCode's Trees section (validate BST, lowest common ancestor, level-order traversal, max depth) - at least 8 problems.

Checkpoint: Build from scratch, unaided - implement BST delete with the two-children case correctly (this is the case people get wrong). Closed-book explanation of why an unbalanced BST degrades to O(n).

1.11 Heaps & Priority Queues

Objective: Know when a problem needs a heap (top-K, merge-K, running median) and use Python's heapq correctly, plus understand the underlying array-based implementation.

Teaching sessions (~40 min): one sitting - the heap invariant, sift-up/sift-down, and heapq usage form one self-contained story; no split needed.

  • Watch: the Heaps section of Data Structures and Algorithms in Python (freeCodeCamp)
  • Read: §7.8–7.10 ("Priority Queues with Binary Heaps" through "Binary Heap Implementation") in the Trees and Tree Algorithms chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python, and the Python heapq docs - heaps are covered inside the Trees chapter here, not as their own chapter.
  • Do: Implement a min-heap from scratch on top of a plain array (sift-up/sift-down), no heapq. Then solve NeetCode's Heap section (kth largest element, top-K frequent, merge K sorted lists) using heapq.

Checkpoint: Closed-book - explain how sift-up/sift-down maintain the heap invariant, and why insert/extract-min are O(log n). Practical: from-scratch heap passes your own unit tests.

1.12 Graphs

Objective: Implement BFS, DFS, topological sort, and Dijkstra's algorithm from scratch; recognize which traversal a problem needs.

Teaching sessions (~40 min each):

  • 1.12a Graph Representation, BFS & DFS - adjacency lists vs. matrices, and the two fundamental ways to explore a graph.
  • 1.12b Topological Sort - ordering tasks with dependencies (Kahn's algorithm).

  • 1.12c Dijkstra's Algorithm - shortest paths when edges have different costs.

  • Watch: the Graphs section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: the Graphs and Graph Algorithms chapter - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python
  • Do: Represent a graph with an adjacency list, implement BFS, DFS (recursive and iterative), topological sort (Kahn's algorithm), and Dijkstra's shortest path - all from scratch. Solve NeetCode's Graphs section - at least 8 problems (number of islands, course schedule, clone graph, network delay time).

Checkpoint: Timed, closed-book - given an unseen graph problem, correctly choose BFS vs DFS vs Dijkstra within 2 minutes and justify the choice, then implement it correctly in 30 minutes.

1.13 Dynamic Programming & Greedy Algorithms

Objective: Recognize overlapping subproblems and optimal substructure; convert a brute-force recursive solution into memoized/tabulated DP; know when greedy is provably correct vs when it isn't.

Teaching sessions (~40 min each):

  • 1.13a From Recursion to Memoization to Tabulation - the DP mindset: brute-force recursion → cache the repeated work → flip it into a bottom-up table.
  • 1.13b Classic DP Patterns - knapsack, longest common subsequence, longest increasing subsequence - the "shapes" most DP interview questions are variations of.

  • 1.13c Greedy Algorithms - making the locally-best choice, and how to tell (and prove) whether that's actually globally optimal.

  • Watch: the DP/Greedy section of Data Structures and Algorithms in Python (freeCodeCamp)

  • Read: §5.12 Dynamic Programming - Runestone Academy, Problem Solving with Algorithms and Data Structures using Python, Recursion chapter for the intro (it's one section inside the Recursion chapter, not its own chapter, and only walks through the coin-change problem) - plus, for the depth this lesson actually needs (LCS, knapsack, LIS, and greedy proofs), Chapter 3: Dynamic Programming and Chapter 4: Greedy Algorithms from Algorithms by Jeff Erickson (free, UIUC)
  • Do: Solve the classic DP progression yourself, closed-book, in order: Fibonacci (memoized), climbing stairs, coin change, longest common subsequence, 0/1 knapsack, longest increasing subsequence. Then 3 greedy problems from NeetCode (jump game, gas station, task scheduler).

Checkpoint: Build from scratch, unaided - given an unseen medium DP problem, correctly define the recurrence relation and base case in writing before coding (this is the step people skip and then flail). 45-minute time box.

1.14 Phase Capstone

Objective: Prove you can combine everything in this phase, both by building and under interview-like pressure.

Teaching sessions: none - this is an assessment, not a taught lesson. It only requires your independent work plus a review conversation once you're done.

Do - Part A (Build): Implement a small "DSA library" module in Python: singly + doubly linked list, array-backed stack and queue, min-heap, hash map with collision handling, BST with insert/search/delete, and a graph with BFS/DFS - all from scratch, no relying on list/dict/heapq/deque internals for the core logic. Write unit tests for each.
Do - Part B (Timed assessment): 6 mixed problems from NeetCode 150, one per major topic (array, linked list, tree, graph, heap, DP), 3 hours, closed-book.

Checkpoint:

  • Your library passes your own unit tests.
  • 5/6 minimum on the timed set.
  • If you fail: identify which topic broke down, redo that lesson's checkpoint, retry the capstone's timed portion (not the whole thing) before starting Phase 2. Log the failure in mistakes-log.md.
